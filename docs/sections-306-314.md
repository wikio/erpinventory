# Sections 306–314 — Payslip References, Holiday Sources & Onboarding Polish

## 306. Payslip reference code — new format

Payslips now use `SARI-PAY{YY}{MM}{PAYTYPE}{DD}-{EMPSEQ}`:

- `{YY}` / `{MM}` / `{DD}` — payment year / month / day (from the payment date),
- `{PAYTYPE}` — first two letters of the configured Payment Type (Section 300.4): `AN` annual, `MO` monthly, `WE` weekly, `DA` daily, `PI` piecework/occasional,
- `{EMPSEQ}` — the employee's own EMP-type sequence (5 digits, padded).

Example: monthly payslip paid 2026-03-05 for employee sequence 42 → `SARI-PAY2603MO05-00042`. The `PAY` document-code mask is updated automatically at DB init, the `ReferenceCodeManager` supports the `{DD}`, `{PAYTYPE}` and `{EMPSEQ}` tokens, and the payslip editor exposes a Payment-Type selector. Existing records are re-referenced on the next save/backfill.

## 307. Leave calendar — Algerian weekend & Sunday-first layout

The default work week is now **Sunday → Thursday**, with **Friday/Saturday as the weekend**. Calendar grids start on Sunday (first working day) and always show the configured weekend days last; the column order is computed live from the work-schedule configuration (Section 300.3) via `weekColumnOrder()`, so changing the weekend days in Leave → Configuration immediately reflows the calendar.

## 308. Public holidays menu title translation

The `publicHolidays` key is now translated in French, Arabic and English ("Jours fériés" / "العطل الرسمية" / "Public holidays") — no more raw key in the Leave Manager tabs.

## 309. Public holidays — import, auto-fetch & auto-calculation

- **309.1 File import** — CSV or JSON files are imported through a **configurable column mapping** (date, FR/AR/EN names, fixed/variable flag, notes), persisted per format in `settings/holiday-config`. Parsing/mapping logic lives in `src/core/holiday-import.ts`.
- **309.2 Server-side auto-fetch** — a new `holidays` kind in the portable-content repository (`file-content.js`) exposes the designated server folder through `GET /api/content/holidays` and `GET /api/content/holidays/{file}`. **Ready-to-import files covering 2011 → 2031** ship in `content/holidays/*.json` (generated by `scripts/generate-holiday-files.js`). On the holidays page the app auto-imports missing years (toggleable) and offers a "Sync now" button.
- **309.3 Year filter** — searchable autocomplete year selector (datalist), defaulting to the current year.
- **309.4 Religious holiday sources** — each holiday records its `source` (`auto` / `csv` / `json` / `manual`). The default source is **automatic calculation** through the tabular Hijri calendar (`src/core/hijri.ts`, exposed as `SariCore.hijri`); a "calculate" button applies the computed religious dates for the selected year. Any manual correction of an entry switches its source to `manual`, so corrections survive future recalculations — every entry stays editable.

## 310. Payslip fiscal identifiers (NIF / NAI / NIS / RC)

The payslip consultation and templates now resolve NIF, NAI, NIS and RC through `resolveFiscalIdentifiers()`: identifiers are pulled from company settings (Section 283), and when a payslip is linked to one of the company's **trade registers (RC)**, that register's identifiers are used (with per-field fallback to settings). The payslip editor offers an RC selector with a live fiscal preview; the trade-register manager (Direction de Commerce) now records NIF/NAI/NIS per register. `payslips.payment_type_id` and `payslips.rc_id` columns are added (schema + migration `010_payslip_reference_fiscal.sql` + external connector mappings).

## 311. Payslip consultation — GED stacking fix

`DocumentManager` now computes its z-index dynamically above any visible overlay (same approach as the Section 298 fix), so the "Employee GED" / "Payslip GED" modals open **above** the payslip consultation instead of behind it, and a **"Back to consultation"** action is shown when a parent consultation is open underneath.

## 312. Payslip templates — modernized design & configurable header/footer

- New **modern default template** (`doc-tpl-payslip-modern`) with clearly bordered earnings/deductions tables, plus **3 additional designs** (`clinical`, `amber`, `midnight`); the classic template remains available.
- Every template now carries a **configurable header** (company logo + fiscal identifiers) and **footer** (company address + document reference), edited through "En-tête / pied" (rich HTML, `{{…}}` fields), rendered via the Section 199 `documentShell` header/footer library.

## 313. Portal onboarding refresh fix

After reading/signing the work rules, terms, contract or submitting the conflict declaration, the portal now **re-renders immediately** so the "My Onboarding Journey" stepper, progress bar and alert update without a manual page reload; the wizard then continues at the next pending step.

## 314. Detailed work rules & general terms templates

`src/core/hr-policies.ts` ships article-by-article model texts for the **Work Rules** (20 articles: hours & time tracking, Algerian week/holidays, leave, confidentiality, IT use, medical-device traceability, safety, conflicts of interest, disciplinary scale & procedure, termination, publication) and the **General Terms** (10 articles), each in FR/AR/EN and rendered as numbered articles. They are seeded as **version 2** of the published documents (older v1 acceptance is re-prompted automatically) and remain fully editable in Contrats → Règlement intérieur / CGU before adoption as the official policy.
